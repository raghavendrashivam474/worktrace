## 2. Feature Implementation Deep-Dive (S1.4)

To support task organization, `TasksScreen` was heavily refactored. We transitioned from a stateless `ConsumerWidget` to a `ConsumerStatefulWidget` to maintain local UI state without polluting the Riverpod global scope.

### 2.1 Task Editing
*   **State Implementation:** Added `editTask(String id, String newTitle)` to `TaskListNotifier`. This fetches the existing task, applies `task.updateTitle(newTitle)` (which inherently validates for empty/whitespace strings and updates the `updatedAt` timestamp while preserving `createdAt`), and passes it to `TaskRepository.updateTask()`.
*   **UI Implementation:** Added an edit action to `_TaskListItem` that triggers a pre-filled dialog.

### 2.2 Search, Filter, and Sort (In-Memory Pipeline)
Rather than writing custom SQLite queries and exposing Drift to the UI, all list organization is executed in-memory against the `AsyncValue.data` emitted by `taskListProvider`.
*   **The Pipeline:** The UI runs a linear transformation on every build: `raw tasks` $\rightarrow$ `_applyFilter()` $\rightarrow$ `_applySort()` $\rightarrow$ `ListView`.
*   **Search (`_searchController`):** Evaluates `task.title.toLowerCase().contains(query)`. The `TextField` includes a dynamic suffix icon to clear the query. Unmatched queries trigger a distinct `WtEmptyState` ("No matching tasks") to differentiate from an empty database.
*   **Filtering (`TaskFilter` enum):** Implemented via Material 3 `SegmentedButton` (All / Active / Done). Toggling a task's checkbox immediately re-evaluates its membership in the active filter.
*   **Sorting (`TaskSort` enum):** Implemented via `PopupMenuButton`. Provides deterministic list sorting using `List.sort()`:
    *   *Newest First:* `b.createdAt.compareTo(a.createdAt)`
    *   *Oldest First:* `a.createdAt.compareTo(b.createdAt)`
    *   *Title A-Z:* Case-insensitive string comparison.

## 3. Reliability, Hardening, & Lifecycle Safety (S1.5)

S1.5 focused strictly on resolving brittle UI patterns and ensuring the app fails gracefully when persistence layers throw exceptions.

### 3.1 Dialog Controller Lifecycle Rewrite (Critical Fix)
*   **The Problem:** S1.1–S1.3 used a brittle workaround in `_showCreateDialog`: `Future.delayed(const Duration(milliseconds: 300), controller.dispose)`. This risked memory leaks if the animation hung, or `StateError`s if the user rapidly navigated away while the timer was running.
*   **The Solution:** Extracted the dialog into a self-contained `_TaskFormDialog` `StatefulWidget`. 
*   **Mechanics:** The `TextEditingController` is now instantiated in `initState()` and safely destroyed in `dispose()`. The dialog simply pops with the `String` result, returning control to `TasksScreen` to execute the Riverpod mutation.

### 3.2 Viewport Overflow & Responsive Layout Fix
*   **The Problem:** During QA on tablet profiles, minimizing the app to a floating window/picture-in-picture mode (e.g., 320x300 dp) caused severe `BOTTOM OVERFLOWED` exceptions. `WtEmptyState` and `_ErrorState` utilized rigid `Column` layouts with large, inflexible padding.
*   **The Solution:** Wrapped the `Column` inside a `SingleChildScrollView` with responsive padding. If the vertical viewport shrinks below the content height, the empty state smoothly becomes scrollable.
*   **Verification:** Added a custom widget test explicitly simulating a 320x300 dp surface size to prevent future regressions.

### 3.3 Mutation Failure & Error Feedback
*   **The Problem:** Previously, if a SQLite operation failed during `create`, `edit`, `toggle`, or `delete`, the exception was swallowed by Riverpod's async guard, or threw unhandled in the UI layer, leaving the user unaware of the failure.
*   **The Solution:** Wrapped all mutator calls in the UI with `try { ... } catch (_)`. Upon failure, `context.mounted` is checked, and a `ScaffoldMessenger.showSnackBar` is displayed with a non-technical error string (e.g., `"Failed to update task state."`).

## 4. Technical Debt Resolution Matrix

The Phase 1 brief identified 7 reported technical debt items. Here is how they were addressed:

| Identified Debt | Resolution |
| :--- | :--- |
| **1. Tasks cannot be edited.** | **Resolved.** Editing workflow implemented end-to-end via `_TaskFormDialog`. |
| **2. List data reloads rather than using reactive Drift streams.** | **Accepted (DEC-019).** Evaluated `watchAllTasks()`, but opted to retain reload-after-mutation. It guarantees absolute consistency, simplifies state, and performs perfectly at local-first scale. |
| **3. SQLite second-level timestamp precision.** | **Accepted (DEC-020).** Second-level precision is fully sufficient for "Newest/Oldest" sorting. Test fixtures were updated to use truncated DateTimes to ensure deterministic testing without schema migrations. |
| **4. Timestamps assume local-time.** | **Deferred.** Local time semantics are appropriate for a local-first workspace. Migrating to UTC is out-of-scope until cross-device syncing is introduced. |
| **5. Controller disposal workaround.** | **Resolved.** Refactored into `_TaskFormDialog` utilizing standard widget `dispose()`. |
| **6. Deletion has no undo.** | **Deferred.** Explicit confirmation dialogs prevent accidental deletion. Soft-delete/undo requires schema changes and was deemed out-of-scope for Phase 1. |
| **7. Search, filter, sort missing.** | **Resolved.** Complete in-memory pipeline implemented. |
