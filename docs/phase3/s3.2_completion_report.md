attach existing snippets to tasks, view linked snippets, and unlink them

## Key Decisions

1. **Separate capability boundary.** Task and Snippet domain models, providers,
   and screens are unchanged. The association lives in `lib/features/links/`.

2. **Check-then-insert for duplicates.** Instead of catching SqliteException
   (which would require adding `sqlite3` as a direct dependency), the
   repository checks for existing links before inserting. Safe for local-first
   single-user app.

3. **FK cascade via PRAGMA.** SQLite foreign keys are disabled by default.
   Added `PRAGMA foreign_keys = ON` in `beforeOpen` to ensure `ON DELETE
   CASCADE` actually fires when tasks or snippets are deleted.

4. **Bottom sheet UI.** Linked snippets are shown in a modal bottom sheet
   triggered by a link icon on each task row. This avoids rewriting the
   Task screen and keeps the association UI self-contained.

## Known Limitations

- Attach picker shows all snippets. For very large snippet collections, a
  search filter would improve usability. Deferred to a future sprint.
- Creating a new snippet directly from a task is not supported. Users must
  create the snippet first, then attach it. This matches the approved design.
