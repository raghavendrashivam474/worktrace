## Key Decisions

1. **Merge-without-overwrite import policy.** Existing records are never
   modified. New records are inserted. Duplicate IDs are skipped. Links
   referencing missing entities are skipped. A summary is reported.

2. **Validation before mutation.** The entire file is parsed and validated
   (format ID, version, structure) before any database writes occur.

3. **No partial imports.** If validation fails, nothing is written. If
   individual records fail during import, they are skipped and reported
   in the errors list — the rest of the import continues.

4. **Export format versioning.** The JSON includes `"format": "worktrace-export"`
   and `"version": 1`. Future versions can check the version number and
   migrate or reject unsupported formats.

5. **Timestamps as ISO-8601 UTC.** All DateTime fields are serialized as
   UTC ISO-8601 strings, preserving the existing domain model semantics.

## Export Schema (v1)

```json
{
  "format": "worktrace-export",
  "version": 1,
  "exportedAt": "2025-07-11T12:00:00.000Z",
  "tasks": [{ "id", "title", "isCompleted", "createdAt", "updatedAt" }],
  "snippets": [{ "id", "title", "code", "language", "createdAt", "updatedAt" }],
  "links": [{ "taskId", "snippetId", "linkedAt" }]
}
```

## Known Limitations

- Export writes to a temporary file before sharing. The temp file is not
  explicitly cleaned up (the OS handles this).
- Import does not use a database transaction for the full import. Individual
  record failures are caught and skipped, but a mid-import crash could
  leave a partial state. This is acceptable for a local-first single-user
  app and can be hardened in a future sprint if needed.
- File picker uses file_picker v13 which has a different API from older
  versions. The code uses FilePicker.pickFiles() (static method).
